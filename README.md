# Agentic Engineering: пакет учасника мінікурсу

[Відкрити анкету з підказками](https://genkovich.github.io/ai-work-check/). Вона заповнюється просто на сторінці; завантажувати пакет для цього не потрібно.

Почни з [«Як я працюю з AI: 10 простих запитань»](first-step.html). Оціни кожну звичку від 0 до 4, подивися, який стик ланцюга курсу в тебе найслабший і який урок його розбирає, і натисни «Завантажити result.json». Запитання про практики, яких курс і вчить, тому низький результат на старті очікуваний. Збережи перший результат незмінним і вибери одну звичку з підказки. На анкету можна закласти 3-5 хвилин; це орієнтир, який ще не вимірювали на пілоті.

Для першого уроку достатньо браузера. Якщо переглядаєш пакет на GitHub, обери **Code → Download ZIP**, розпакуй архів і відкрий `first-step.html` локально. Сторінка HTML на GitHub показує код. Анкета працює без встановлення залежностей, сервера чи репозиторію; відповіді не зберігаються автоматично, тому завантаж файл до закриття сторінки. Є також [текстова версія](templates/01-ai-development-audit.md).

Підказки використовують приклад списку покупок: товари вже можна додавати, а ти просиш AI додати позначку «Куплено» біля «Молоко». Додавання нового товару, наприклад «Хліб», має працювати й далі. Це лише ілюстрація; будувати таку сторінку для анкети не потрібно. Відповідай про свої звички, а за відсутності досвіду обирай відповідний варіант.

## Практика з кодом починається з уроку 2

Другий урок присвячено Context Engineering: як дати агенту потрібні інструкції та перевірити їх у новій сесії. Перед практикою прочитай [пояснення контексту з прикладами](docs/lesson-2/concepts.md). Працюй за [десятьма кроками](context-check.html) або [публічною сторінкою](https://genkovich.github.io/ai-work-check/context-check.html). У [підготовці](docs/lesson-2/setup.md) є завантаження, Git, Node, обраний агент і встановлення SDD; у [промптах](docs/lesson-2/prompts.md) готові повідомлення.

### Що вже є

`agent-ops-dashboard` це невеликий локальний застосунок на Node.js та Express. Сервер відповідає на `/api/health`, головна сторінка показує `No slice is wired up yet.`, а два тести перевіряють цей початковий стан. У `fixtures/claude-home/` лежать шість синтетичних сесій у трьох проєктах.

Сесія тут означає одну розмову з агентом, збережену в основному файлі `.jsonl` під текою проєкту. Поруч є вкладені службові файли; їх у перший перелік не включаємо. Особисті розмови для практики не потрібні.

### Яку зміну починаємо

Хочемо бачити список сесій, розуміти, до якого проєкту вони належать, і знаходити недавні. Назвемо фічу `session-index`. Перший навчальний варіант використовує лише метадані файлів: імʼя, розмір, час зміни. Текст розмов і особисті логи не читаємо; у джерело даних застосунок не записує.

Цей короткий опис уже дає мету навчальної задачі. Точні інтерфейси, обробку помилок і критерії перевірки погодимо в уроці 3. Зараз налаштовуємо передачу контексту, без реалізації.

## Швидкий запуск

Повні пояснення й очікуваний результат кожної команди є в [setup.md](docs/lesson-2/setup.md). Потрібні Node.js 22 або 24, Git і редактор. Після clone або розпакування відкрий у редакторі теку з `package.json`, потім звичайний термінал у ній:

```sh
npm ci
npm run verify
npm run demo
```

Виконуй по одній команді. Спочатку очікуємо два успішні тести, потім адресу http://127.0.0.1:4180 і порожню сторінку. Це орієнтири, фактичний результат перевір у своєму запуску.

`npm run demo` через `scripts/demo.mjs` явно задає фікстури й порт 4180. Термінал із сервером залиш працювати, для агента відкрий інший. Сервер зупиняється через Ctrl+C. `npm start` для практики не використовуємо: без налаштувань він вказує на особисту `~/.claude`.

## SDD уже потрібен у другому уроці

Спочатку підготуй Git за [інструкцією](docs/lesson-2/setup.md#3-підготуй-git-агента-й-sdd): після ZIP потрібні власний корінь репозиторію, автор комітів і перший коміт. Після clone історія вже є. Відкрий `.claude/sdd.local.example.md` у редакторі й збережи копію як `.claude/sdd.local.md`, не перезаписуючи наявні налаштування.

Запусти `claude` в корені пакета. Потрібен власний доступ до Claude Code; виклики агента оплачуються за твоїм тарифом. Усередині Claude Code введи по одній команді:

```text
/plugin marketplace add genkovich/sdd
/plugin install sdd@sdd
/reload-plugins
```

У Codex або Cursor вибери відповідний спосіб встановлення в [підготовці](docs/lesson-2/setup.md); встановлювати всі три інструменти не потрібно. Далі за [промптами](docs/lesson-2/prompts.md) прочитай основні інструкції, запусти survey й перевір карту. Потім розбери вкладені інструкції та правила й перевір нову сесію. Реалізацію на цьому уроці не починаємо.

Для уроку 3 є [десять послідовних кроків](docs/lesson-3/README.md) і [запити A–F](docs/lesson-3/prompts.md). Починаємо з пояснення вимог, потім готуємо документи; код змінюватимемо в уроці 4. Скорочений SDD-маршрут тут є явним навчальним рішенням: опис нового API та станів сторінки залишається у SAD і задачах. Не переносимо цей пропуск автоматично на інші проєкти.

## Свій проєкт

Перший прохід зручніше зробити на цьому кіті. Свій проєкт підходить, якщо його безпечно запускати й передавати агенту. Там теж можна почати з survey і перевірки чинних інструкцій; мету та критерії зміни погодь для власної задачі.

## Коли пакет пройдено

Прийнятий зріз за [Verification Canvas](templates/05-verification-canvas.md): усі AC зрізу мають докази на одному коміті, незалежне ревʼю зроблене, знахідки мають рішення, межі названі. CI з `.github/workflows/verify.yml` запускається лише у твоєму форку на GitHub; локальний `npm run verify` він не заміняє. Потім [фінальна анкета](final-step.html) уроку 6: 35 складніших запитань про роботу з агентами по тих самих пʼяти стиках. Стартовий файл вона не читає, але поклади його поруч: по стиках видно, що змінилось. Окремо запиши один приклад із практики й результат його перевірки за [шаблоном уроку 6](templates/06-delta-audit.md). Бали описують звички й не доводять працездатності коду. Заповнені файли без прогону перевірок пакет не закривають.

## Якщо щось не працює

Якщо практика зупинилася на помилці, почни з її тексту. Нижче зібрані ситуації, які можуть трапитися під час запуску пакета й роботи з агентом. Знайди схожу на свою та пройди запропоновані перевірки. Не кожна помилка означає, що ти вже щось зламав у фічі: іноді термінал просто відкритий не в тій теці.

### Термінал не знаходить Node або не запускає пакет

Якщо команда `node` або `npm` не знайдена, встанови Node 22 або 24 LTS з [nodejs.org](https://nodejs.org/en/download). Після встановлення відкрий новий термінал і виконай `node --version`, щоб побачити доступну версію.

Якщо `npm ci` зупиняється на lock-файлі, перевір поточну теку. Ти маєш бути в корені пакета, поруч із `package.json`. Також перевір Node: версії нижче 20 пакет не підтримує.

Поточний `npm run demo` запускає `scripts/demo.mjs` без `--env-file`. Якщо бачиш `bad option: --env-file`, перевір версію пакета й команду в `package.json`: імовірно, це старі матеріали. Для курсу перевір Node 22 або 24 й візьми актуальний пакет, зберігши власні документи.

### Сервер не може відкрити порт

Якщо порт 4180 зайнятий, можливо, твій попередній запуск дашборда ще працює. Повернися до його термінала й зупини через Ctrl+C. Навчальний launcher фіксує порт 4180; зміна `.env.fixtures` чи успадкованого `PORT` його не перемикає. Якщо порт займає інша потрібна програма, постав практику на паузу й узгодь запуск із командою курсу. Чужі процеси зупиняти не потрібно.

Помилки `EPERM` чи `EACCES` на `listen` означають, що середовище забороняє локальний сервер. Дозволь localhost або повтори запуск у звичайному терміналі. Такий результат стосується середовища; його не можна записувати як RED, що доводить відсутню поведінку твоєї задачі.

### На сторінці не те, чого ти очікував

Якщо після своїх змін бачиш свої справжні сесії замість шести навчальних, ти запустив `npm start` без змінних оточення. У такому режимі дашборд читає `~/.claude`. Зупини його й запусти `npm run demo`. Сам дашборд лише читає диск, нічого не записує й слухає `127.0.0.1`; дані через нього нікуди не надсилалися.

Порожня сторінка «No slice is wired up yet» на старті очікувана. Список сесій ти додаватимеш під час курсу. Для практики вистачить даних із `fixtures/`, домашню теку `~/.claude` підключати не потрібно.

Якщо список є, але порядок «від свіжих» не збігається з датами в файлах, ти запустив сервер не через `npm run demo`, а напряму. Git не зберігає mtime, після clone усі шість файлів мають одну дату; `predemo` і `preverify` вирівнюють їх скриптом `scripts/pin-fixture-mtimes.mjs`. Запусти його рукою або перезапусти через `npm run demo`.

### Агент не знаходить документ або команду SDD

Коли `/sdd:specify` не бачить карти архітектури, перевір теку агента й результат уроку 2. Файл `docs/architecture-map.md` створює survey. У чистому стартовому пакеті карти навмисно немає. Повернися до цього кроку; готовий приклад лектора не копіюй.

Якщо в списку взагалі немає команд `/sdd:…`, плагін може бути не встановлений або ще не перезавантажений. Виконай `/plugin install sdd@sdd`, потім `/reload-plugins`. У Codex і Cursor назви відрізняються: шукай `$sdd-specify` або `/sdd-specify`, як описано в README SDD.

### Перевірки зупинили роботу

Якщо `/sdd:implement` вимагає lint, у цьому репозиторії лінтера справді немає. Постав `gate_lint: false` у `.claude/sdd.local.md` або зафіксуй це у Verification Canvas: перевірка ввімкнена, але команди для неї не налаштовано.

Якщо після твоїх змін `npm run verify` показує червоний тест, прочитай його назву й перший assertion. Вони допоможуть зрозуміти, яка поведінка змінилася. Збереження старої поведінки скелета входить до AC, тому міняти очікування двох стартових тестів лише заради зеленого результату не можна.

Якщо тест зелений у тебе і червоний у CI на Windows, глянь, чи не викликає він `find`, `grep`, `wc` або `jq` через shell. Таких команд там немає. Підрахунки з диска роби через `test/oracle.js`, він на чистому Node.

Гілки Node звірені з [таблицею релізів](https://nodejs.org/en/about/previous-releases) на 2026-09-06: 22 і 24 в LTS, 20 вже EOL.
