# AI Development Audit - <slug>

Почни з того, що можеш пригадати й підтвердити про останню задачу з агентом. У цьому аудиті немає балів: ми фіксуємо початок роботи, щоб наприкінці курсу було з чим порівняти результат. Якщо чогось не вимірював, так і напиши. Перші три розділи стосуються минулої задачі, а з четвертого ти вже обиратимеш задачу на курс.

## 2. Шість блоків: стан і доказ

<!-- instruction: для кожного блоку один із пʼяти станів: «не роблю», «частково»,
«підтверджено», «ще не перевірено», «не застосовується: причина». «Підтверджено» вимагає
доказу в третій колонці: шлях до файлу, команда з виводом, посилання на PR. Впевнена
самооцінка доказом не є.

Шість блоків це області роботи. Стиків між сімома фазами ланцюга
(Intent → Context → Spec → Plan → Implementation → Verification → Learning) теж шість,
але це інша одиниця: Execution обʼєднує Plan і Implementation. «4,5 стика з 6» із цієї
таблиці не виводиться. -->

| Блок | Що перевіряю | Стан | Доказ або чого бракує |
|---|---|---|---|
| Intent | Мета і межа задачі записані до реалізації, не в голові | | |
| Context | Факти й обмеження, яких у коді не видно, лежать у файлі, який агент читає сам | | |
| Spec | Очікувана і захищена поведінка сформульовані так, що їх можна перевірити без автора | | |
| Execution | Кроки, залежності й межі делегування відомі до запуску агента | | |
| Verification | Є перевірка саме нової поведінки; зелений старий набір її не заміняє | | |
| Learning | Після помилки зʼявився детектор або правило, і його перевірили контрприкладом | | |
