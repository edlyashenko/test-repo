# Урок 2. Context Engineering

Теорія цього уроку є в уроці LMS; тут лише практика.

## Мета

Запустити готовий навчальний застосунок, встановити SDD в обраному агенті й отримати від survey перевірену карту архітектури `docs/architecture-map.md`. Наприкінці нова сесія агента має правильно пояснити код і правила лише за файлами проєкту. Код, тести й залежності на цьому уроці не змінюємо. Команди виконуй по одній і чекай, поки термінал знову запропонує ввід.

## Що має бути готове

- Редактор, Git і Node.js 22 або 24: [VS Code](https://code.visualstudio.com/download), [Git](https://git-scm.com/downloads), [Node.js](https://nodejs.org/en/download). Після встановлення відкрий новий термінал.
- Доступ до [репозиторію пакета](https://github.com/genkovich/agentic-engineering-mini-kit) у своєму GitHub-акаунті. Якщо бачиш 404, перевір акаунт і прийняте запрошення; публічний чекліст доступу до приватного коду не дає, звернися до команди курсу.
- Власний доступ до одного агента: Claude Code (основний показ у відео), Codex CLI або Cursor. Виклики агента оплачуються за твоїм тарифом; сам дашборд і тести модель не викликають.
- Тека для навчальних проєктів, яка не лежить усередині іншого Git-репозиторію.

## Кроки

### 1. Завантаж і відкрий проєкт

У терміналі перейди у свою теку для навчальних проєктів і скопіюй репозиторій:

```sh
git clone https://github.com/genkovich/agentic-engineering-mini-kit.git
cd agentic-engineering-mini-kit
```

При запиті входу використовуй свій налаштований GitHub-доступ. Токени не вставляй у промпт чи матеріали. Якщо тека вже існує, не перезаписуй її: перевір, чи це потрібна копія.

Альтернатива: **Code → Download ZIP**, потім розпакуй архів. Windows: **Extract All / Видобути все**; macOS: подвійне натискання. Працюй із розпакованою текою, де лежить `package.json`. Для ZIP у кроці 3 є короткий додатковий крок Git.

У VS Code вибери **File → Open Folder**, відкрий цю теку, потім **Terminal → New Terminal**. Перевір інструменти:

```sh
node --version
npm --version
git --version
```

Перша команда має показати `v22.` або `v24.`. Дві інші показують свої версії. Якщо команда не знайдена, повернися до встановлення; не продовжуй навмання.

### 2. Перевір і запусти застосунок

```sh
npm ci
```

Це встановлює залежності за `package-lock.json` і потребує інтернету. Дочекайся успішного завершення. `ENOENT` зі згадкою `package.json` зазвичай означає неправильну теку: перевір її в редакторі й відкрий новий термінал.

```sh
npm run verify
```

Очікуємо три тести без падінь. Приклад підсумку, це не результат твого запуску:

```text
tests 3
pass 3
fail 0
```

Ці тести перевіряють health-відповідь, HTML-оболонку з її політикою безпеки і скрипт теми. Список сесій вони ще не перевіряють, бо він не реалізований. Збережи фактичний вивід у своїх нотатках або історії термінала; окремий документ для цього не вимагається.

```sh
npm run demo
```

Дочекайся адреси http://127.0.0.1:4180 і відкрий її в браузері. Має бути `No slice is wired up yet.`: шість навчальних файлів сесій лежать на диску, але списку на сторінці ще немає. Додатково відкрий http://127.0.0.1:4180/api/health і перевір, що `claudeHome` вказує на `fixtures/claude-home`.

Цей термінал зайнятий сервером. Для наступних команд відкрий **Terminal → New Terminal** у тій самій теці. Сервер завершується через **Ctrl+C**. При `EADDRINUSE` порт 4180 зайнятий: зупини власний попередній запуск, невідомі процеси навмання не завершуй.

Запуск через `scripts/demo.mjs` примусово задає фікстури та порт 4180, а `predemo` перед ним вирівнює дати файлів. Не використовуй `npm start` і особисту `~/.claude` для цієї практики.

### 3. Підготуй Git і налаштування SDD

Survey записує карту в Git і привʼязує її до коміту, тому потрібна власна Git-копія. Після clone виконай:

```sh
git rev-parse --show-toplevel
git status --short
```

Перший результат має бути шляхом саме до відкритої копії пакета. Якщо показано батьківську теку, зупинись: перенеси навчальну копію поза чужий репозиторій і відкрий її заново. Не запускай SDD у корені особистих нотаток чи іншого проєкту.

Після ZIP відкрий термінал у розпакованій теці пакета і виконай:

```sh
git init
git rev-parse --show-toplevel
```

Звір корінь так само. Для обох способів перевір автора комітів:

```sh
git config user.name
git config user.email
```

Якщо значень немає, задай свої **локально для цього репозиторію**. Заміни текст у лапках на своє імʼя та адресу, яку дозволяєш бачити в комітах; можна взяти GitHub noreply-адресу з налаштувань акаунта:

```sh
git config user.name "YOUR NAME"
git config user.email "YOUR COMMIT EMAIL"
```

Після ZIP потрібен перший коміт. Спершу переглянь `git status --short`: там мають бути тільки файли навчального пакета, без секретів і чужих документів. Потім:

```sh
git add .
git diff --cached --stat
git commit -m "Start mini-course practice"
```

Після clone початковий коміт уже є; ці три команди повторювати не потрібно. Зміни нікуди не публікуємо.

У редакторі відкрий `.claude/sdd.local.example.md`, вибери **File → Save As** і збережи як `.claude/sdd.local.md`. Це налаштування мови та простого послідовного режиму. Файл уже виключений через `.gitignore`. Наявний власний файл не перезаписуй.

Перед першим скілом постав мітку:

```sh
git tag start
```

Це мітка на стан до практики, щоб наприкінці побачити всі зміни однією командою. Якщо Git скаже, що мітка `start` уже існує, ти ставив її раніше; лиши стару, вона й показує справжній початок.

### 4. Встанови агента й SDD

**Claude Code.** У звичайному терміналі перевір:

```sh
claude --version
```

Якщо команда не знайдена, вибери команду своєї ОС з [офіційного Quickstart](https://code.claude.com/docs/en/quickstart). Інсталятор завантажується і виконується; перед запуском перевір адресу.

macOS, Linux або WSL:

```sh
curl -fsSL https://claude.ai/install.sh | bash
```

Windows, саме PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Відкрий новий термінал і повтори `claude --version`. Якщо запуск досі не працює, звір помилку з [діагностикою](https://code.claude.com/docs/en/troubleshoot-install). Встановлена програма ще потребує акаунта або доступу організації, який підтримує Claude Code.

```sh
claude
```

Під час першого запуску пройди вхід за підказками. Для повторного входу є `/login` усередині Claude Code. Перевір показану теку проєкту та довіряй лише завантаженій навчальній копії. Під час запису не показуй токени й особисті дані.

Наступні команди вводь **усередині Claude Code**, по одній:

```text
/plugin marketplace add genkovich/sdd
/plugin install sdd@sdd
/reload-plugins
```

Відкрий список команд через `/` і знайди `/sdd:survey`. Якщо команда відсутня, перевір повідомлення встановлення, повтори reload або перезапусти Claude Code в цій самій теці. Не вигадуй заміну команди. [Офіційний репозиторій SDD](https://github.com/genkovich/sdd) містить актуальні інструкції.

**Codex або Cursor.** Claude Code встановлювати не потрібно. Відкрий ту саму теку пакета в обраному інструменті; потрібен власний доступ до його агента. Для Codex CLI [інструкція запуску](https://developers.openai.com/codex/cli) пояснює встановлення й вхід: перевір `codex --version` і запускай `codex` з кореня пакета.

SDD для Codex або Cursor встановлюється скриптом у поточний проєкт. На Windows виконуй його у Git Bash або WSL, не в PowerShell. Перед запуском перевір адресу: скрипт завантажується й виконується.

Codex, у звичайному терміналі кореня пакета:

```sh
curl -fsSL https://raw.githubusercontent.com/genkovich/sdd/main/install.sh | bash -s -- codex
```

Перезапусти Codex. У розмові команда карти має назву `$sdd-survey`. Не встановлюй паралельно другий варіант SDD через marketplace: назви й дублікати команд відрізнятимуться.

Cursor, у звичайному терміналі кореня пакета:

```sh
curl -fsSL https://raw.githubusercontent.com/genkovich/sdd/main/install.sh | bash -s -- cursor
```

Перезапусти Cursor або виконай **Developer: Reload Window**. У чаті введи `/` й вибери `sdd-survey`.

Скрипт додає `.agents/skills/` і `.codex/agents/` для Codex або `.cursor/skills/` і `.cursor/agents/` для Cursor. Це очікувані службові файли встановлення; не сприймай появу цих тек як реалізацію фічі.

### 5. Прочитай основні інструкції

Надішли агенту [запит до кроку 5](#крок-5-основні-інструкції). Кореневий `AGENTS.md` уже підготовлений; `CLAUDE.md` імпортує його через `@AGENTS.md`, щоб ті самі інструкції читав Claude Code. Карта HTML-шару лежить у `views/AGENTS.md`, технічні конвенції зон у `.claude/rules/`, а `docs/roadmap.md` тримає, що будуємо далі й у якому порядку. Генерувати ще один набір правил не потрібно.

`AGENTS.md` каже, як ми працюємо, roadmap каже, що робимо далі. Очікуй, що агент назве саме roadmap, коли пояснюватиме заплановану зміну; якщо він виводить її з README або з коду, попроси назвати файл-джерело.

| Інструмент | Як підключається зміст |
|---|---|
| Claude Code | Кореневий `CLAUDE.md` імпортує `AGENTS.md`; вкладені інструкції й scoped rules підключаються при читанні відповідних файлів |
| Codex | На початку збирає `AGENTS.md` від кореня до робочої теки; запуск із кореня не гарантує автоматичне включення `views/AGENTS.md` |
| Cursor | Правило з `globs` підключається, коли відповідний файл є в контексті; підтримує також `AGENTS.md` |

Кореневий AGENTS прямо вимагає читати вкладені інструкції та політику перед відповідною роботою, тому є явний спосіб дістати правила незалежно від автоматичного механізму. Документація: [Claude Code](https://code.claude.com/docs/en/memory), [Codex AGENTS.md](https://developers.openai.com/codex/guides/agents-md), [Cursor rules](https://cursor.com/docs/context/rules). Явне читання не доводить автоматичного підключення; текст правила не замінює права доступу.

### 6. Створи карту через survey

Надішли [запит до кроку 6](#крок-6-перед-survey) і дочекайся, поки агент підтвердить межі. Після підтвердження запусти одну команду свого інструмента:

| Інструмент | Команда |
|---|---|
| Claude Code | `/sdd:survey` |
| Codex зі скриптовим встановленням SDD | `$sdd-survey` |
| Cursor зі скриптовим встановленням SDD | Введи `/` і вибери `sdd-survey` |

Survey створює `docs/architecture-map.md` і може зробити коміт та службові налаштування. Це єдиний обовʼязковий новий документ уроку. Опис бажаної фічі вже є в `docs/roadmap.md`; окремий бриф або інтервʼю для цієї вправи не потрібні.

### 7. Перевір карту

Відкрий карту й названі в запиті файли поруч у редакторі, потім надішли [запит до кроку 7](#крок-7-перевірка-карти).

Що має бути в карті: у `server.js` маршрут `GET /` показує порожню сторінку; `lib/claude/index.js` поки визначає шляхи, без читання списку сесій; коментар `lib/sources.js` про відсутність прямих імпортів адаптера не відповідає імпорту `claudeHome` у `server.js`. У карті має бути фактична поведінка, відділена від планів і коментарів.

Якщо потрібен зрозуміліший формат, попроси таблицю «твердження | стан | джерело» й дай один-два зразки з уже відкритих файлів, наприклад «GET / показує порожню сторінку | є зараз | server.js».

### 8. Розбери вкладені інструкції

Надішли [запит до кроку 8](#крок-8-вкладені-інструкції). Зміст лежить один раз у `views/AGENTS.md`; `views/CLAUDE.md` імпортує його для Claude Code. Очікуй пояснення `layout()`, `esc()` і Content-Security-Policy, звіряючи його з `views/layout.js`.

### 9. Розбери правила зони

Надішли [запит до кроку 9](#крок-9-правила-зони). Технічні конвенції лежать у `.claude/rules/javascript.md` з `paths: ["**/*.js", "**/*.mjs"]`, тому Claude Code підтягує їх сам, коли відкриває `lib/claude/index.js`. Cursor читає дзеркало `.cursor/rules/javascript.mdc`. Межі роботи з даними сесій живуть у розділі «Межі» в `AGENTS.md`: вони діють у всьому застосунку, тому місце їм у корені.

### 10. Перевір нову сесію

Спочатку збережи перевірену `docs/architecture-map.md`. Потім відкрий сесію без історії:

- Claude Code: `/exit`, далі `claude` у звичайному терміналі тієї самої теки, без resume або continue.
- Codex: `/new` у поточній CLI-сесії.
- Cursor: новий чат у тому самому проєкті без копіювання старої розмови.

Надішли [запит до кроку 10](#крок-10-нова-сесія). Прочитай відповідь і звір її з кодом, інструкціями й картою. Запиши у поля [чекліста](https://genkovich.github.io/ai-work-check/context-check.html#evidence), який інструмент використано, що він пояснив правильно, які файли відкрив явно й що залишилося неперевіреним.

Запит перевіряє, чи можна продовжити роботу за файлами. Він не доводить автоматичне завантаження: агент може знайти й відкрити інструкції явно. Без виконаного запуску нової сесії крок лишається незавершеним.

### 11. Переглянь зміни й збережи результат

Повтори `npm run verify`. Далі порівняй поточний стан із міткою `start` із кроку 3:

```sh
git log --oneline start..HEAD
git diff start HEAD
git diff HEAD
git status --short
```

Перша команда показує нові коміти. Друга показує закомічені зміни. Третя показує зміни після останнього коміту; нові невідстежувані файли видно в останній команді, їх відкрий окремо. Якщо survey не робив коміта, перші дві команди нічого не покажуть, а карта буде видна в `git status --short`.

Очікуємо карту та службові зміни обраного способу встановлення SDD. Код, тести й залежності залишаються незмінними. Уточнення інструкцій допустиме лише після твоєї перевірки та погодження; якщо карта вже точна, переписувати її або правила для позначки не потрібно.

У [чеклісті](https://genkovich.github.io/ai-work-check/context-check.html#evidence) є поля для інструмента, фактичних запусків, перевірки нової сесії та обмежень. Вони не зберігаються автоматично. Натисни **Зберегти результат текстом** до закриття сторінки; отримаєш один Markdown-файл із позначками й власними записами. Не вставляй секрети або приватні розмови.

### Якщо інструкцію справді варто уточнити

Не потрібно змінювати готовий файл лише для позначки про виконання. Якщо помітиш конкретну проблему, попроси запропонувати одне точне уточнення з поясненням, перевір його й лише потім дозволь зміну відповідного канонічного файла. Адаптери не повинні отримати ще одну копію політики. Замінюй цитату лише власною реальною знахідкою; наявність помилки не є умовою завершення уроку.

```text
У відповіді або інструкції є твердження: «ВСТАВ КОНКРЕТНУ ЦИТАТУ».
Звір його з відповідним кодом і назви файл та функцію.
Поясни розходження та запропонуй найменше точне виправлення.
Зараз нічого не змінюй; дочекайся мого погодження.
Після погодженої правки повторно перевір джерело й пояснення.
Якщо розходження не підтверджується, скажи про це.
```
