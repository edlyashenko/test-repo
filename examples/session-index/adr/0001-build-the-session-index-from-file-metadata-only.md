# 0001 - Build the session index from file metadata only

- **Status:** Accepted
- **Date:** 2026-09-06
- **Deciders:** лектор, Tech Lead

## Context

Перший зріз має показати перелік сесій, а файли сесій можуть бути великими (десятки мегабайтів на реальній домашній теці). Треба вирішити, звідки індекс бере проєкт, розмір і час: з метаданих файлової системи чи з вмісту файлу (перший і останній `timestamp`, `cwd`, `ai-title`). Рішення визначає, що саме читає адаптер і як швидко відповідає сторінка.

## Decision drivers

- spec §6: ≤ 100 ms на фікстурах і 0 байтів вмісту прочитано.
- spec §3 non-goals: заголовки, таймлайн і токени лишаються наступним крокам, які читатимуть вміст.
- `docs/architecture-map.md` §Constraints: диск ще не читається; перша функція читання задає конвенцію для решти.
- idea-brief §"Наступний крок беклогу": «лише з метаданих файлової системи (fstat), без читання вмісту».

## Considered options

1. **Лише метадані файлу** - `readdir` + `stat`: імʼя дає `sessionId`, тека дає проєкт, `stat` дає розмір і mtime.
2. **Читати перший і останній рядок файлу** - точніший час активності (останній `timestamp`) і справжній `cwd` замість похідного шляху, ціною відкриття кожного файлу.

## Decision outcome

**Chosen:** Option 1. Перелік не відкриває жодного файлу: ціль ≤ 100 ms і «0 байтів» виконується конструктивно, а не оптимізацією. Похідний шлях проєкту з позначкою (spec AC-01d) це ціна цього вибору, і вона названа в spec.

## Consequences

**Positive**
- Час відповіді не залежить від розміру файлів сесій.
- Наступні кроки додають читання вмісту поверх індексу, не переписуючи його.

**Negative**
- Шлях проєкту відновлюється з імені теки і може не збігатися з оригіналом при дефісах у шляху.
- «Свіжість» це mtime, а не останній `timestamp`; після clone фікстур вони розходяться, поки не спрацює `scripts/pin-fixture-mtimes.mjs`.

**Neutral**
- Перехід на Option 2 пізніше локальний: одна функція в адаптері, ті самі поля у відповіді.
