# agent-ops-dashboard

Локальний дашборд над логами сесій coding-агентів. Читає домашню теку агента з диска (`~/.claude` або `CLAUDE_HOME`), рендерить HTML на сервері й слухає лише `127.0.0.1`. Бази даних, автентифікації та збірки фронтенду немає.

Що вже є, знає код. Карту по ньому пише `survey` у `docs/architecture-map.md`; поки її немає або поки її `reflects_commit` відстає від HEAD, джерело правди це код. Що будуємо далі: `docs/roadmap.md`. Якими словами говоримо про домен: `CONTEXT.md`.

## Як влаштовано

- `server.js`: маршрути Express і складання сторінок.
- `lib/sources.js`: реєстр джерел. Нове джерело це `lib/<vendor>/index.js`, який викликає `registerSource()`. Реєстрація відбувається на імпорті модуля, тому новий адаптер треба ще й імпортувати в `server.js`; без цього рядка `listSources()` мовчки його не покаже.
- `lib/claude/index.js`: адаптер Claude Code. Перед читанням або зміною коду, що працює з джерелом сесій, прочитай `docs/rules/session-data.md`.
- `views/layout.js`: єдина HTML-оболонка. Перед роботою з будь-яким файлом у `views/` прочитай `views/AGENTS.md`.
- `fixtures/claude-home/`: синтетичні сесії для тестів і локального запуску.
- `test/`: `node --test`, файли `*.test.js`. `test/helpers.js` піднімає застосунок на фікстурах, `test/oracle.js` рахує факти з диска.

## Запуск і перевірки

- Node 22 (`.nvmrc`); CI ганяє 22 і 24. Залежності через `npm ci`.
- `npm run demo`: сервер на фікстурах, порт 4180. `npm start` читає справжню `~/.claude`; для розробки й тестів є фікстури, агент `npm start` не запускає.
- `npm run verify` перед кожним комітом. CI ганяє його на Linux, macOS і Windows, тому в тестах не викликай `find`, `grep`, `wc` чи `jq` через shell; для підрахунків із диска є `test/oracle.js`.
- Git не зберігає mtime. `preverify` і `predemo` вирівнюють дати фікстур скриптом `scripts/pin-fixture-mtimes.mjs`; якщо запускаєш тести інакше, спершу виконай його.
- Лінтера немає, ворота це тести. Результат команди записуй таким, яким він був; не запускав, так і пиши.

## Межі

- Джерело сесій лише читаємо. Жодного запису в `CLAUDE_HOME`.
- Справжні транскрипти, ключі й особисті дані в репозиторій не потрапляють. Для прикладів є `fixtures/`.
- CSP в `layout()` і привʼязку до `127.0.0.1` не послаблюй без окремого рішення людини.
- `examples/`: архів готових документів для читання людиною. За основу нових артефактів без прямого прохання не бери.

## Де живуть інструкції

Канонічний текст лежить тут, у `views/AGENTS.md` і `docs/rules/`. `CLAUDE.md`, `.claude/rules/` та `.cursor/rules/` лише імпортують його; правки роби в канонічному файлі. Помітив неточність, спочатку запропонуй правку.
