# Інструкції для agent-ops-dashboard

Це наявний навчальний застосунок. `README.md` пояснює його поточний стан і бажану наступну фічу. Не переходь до реалізації без окремого завдання людини.

## Перед роботою

- Перед читанням або зміною джерела сесій прочитай `docs/rules/session-data.md` і дотримуйся цієї політики. Це єдине місце з правилами даних.
- Перед роботою з будь-яким файлом у `views/` прочитай `views/AGENTS.md`. Якщо інструмент не додав вкладені інструкції автоматично, відкрий файл явно.
- `docs/architecture-map.md` створює survey. Якщо карта вже є, звір її важливі твердження з кодом; вона може застаріти.
- `examples/` містить історичні документи лектора. Не читай і не копіюй їх під час виконання навчальної задачі без прямого прохання людини.
- Не додавай секрети чи приватні дані в репозиторій.

## Запуск і перевірки

- Для практики запускай `npm run demo`. Він використовує `scripts/demo.mjs` і порт 4180. `npm start` у навчальній вправі не використовуємо.
- Перед комітом запускай `npm run verify`. Початковий скелет має два тести; наступні задачі додають свої.
- Runtime-тести не повинні покладатися на shell-команди на кшталт `find`, `grep`, `wc` чи `jq`. Для підрахунків із диска є `test/oracle.js` на Node.
- Git не зберігає mtime. `preverify` і `predemo` вирівнюють дати фікстур через `scripts/pin-fixture-mtimes.mjs`.
- Результат команди записуй фактично. Якщо перевірку не виконано, зазнач це; приклад у документації не є доказом запуску.

## Зміни інструкцій

Готові правила не потрібно переписувати для завершення уроку. Якщо знайдеш неточність, спочатку запропонуй конкретну правку й дочекайся погодження. Змінюй канонічний файл, зберігаючи короткі адаптери інших інструментів.
