# Від завантаження пакета до першого запиту

Тримай цю інструкцію поруч із редактором. Спочатку підготуємо проєкт і побачимо його початковий стан, потім відкриємо агента. Усе робимо в одному пакеті: [genkovich/agentic-engineering-mini-kit](https://github.com/genkovich/agentic-engineering-mini-kit). Він приватний, тому потрібен GitHub-акаунт із доступом від команди курсу.

Це підготовка до [десяти кроків другого уроку](../../context-check.html). Встановлення залежностей потребує інтернету; робота Claude Code потребує окремого доступу до цього інструмента й може оплачуватися за твоїм тарифом. Команди перевірки та дашборд самі модель не викликають. SDD й інші плагіни зараз не потрібні.

## 1. Завантаж і відкрий саме проєкт

У браузері увійди у свій GitHub-акаунт і відкрий посилання на пакет вище. Натисни **Code → Download ZIP**. Дочекайся завантаження, знайди архів у своїх завантаженнях і розпакуй його засобами системи. На Windows для цього є **Extract All / Видобути все**, на macOS архів можна відкрити подвійним натисканням. Працювати безпосередньо всередині ZIP не потрібно.

Відкрий отриману теку й знайди `package.json`. Поряд мають бути `server.js`, `lib/`, `views/`, `fixtures/` і `templates/`. Це корінь пакета. Назва розпакованої теки може містити суфікс гілки, наприклад `-main`; орієнтуйся на файли всередині. Якщо бачиш лише ще одну теку, зайди в неї. Початковий ZIP залиш без змін: якщо в тебе ще немає Git-історії, він допоможе порівняти файли наприкінці уроку.

Якщо GitHub показує 404 або відмову в доступі, постав відео на паузу. Перевір акаунт і прийняте запрошення, потім звернися до команди курсу. Публічна сторінка з чеклістом не надає доступу до приватного пакета. Інший репозиторій або зміна його видимості тут не допоможуть.

### Якщо вже користуєшся Git

Замість ZIP можна взяти HTTPS-копію. У терміналі спочатку перейди у свою теку для навчальних проєктів, потім виконай:

```sh
git clone https://github.com/genkovich/agentic-engineering-mini-kit.git
cd agentic-engineering-mini-kit
```

Це альтернатива завантаженню, не додатковий обов’язковий крок. Якщо Git просить авторизацію, скористайся налаштованим способом входу у свій GitHub-акаунт. Не вставляй токени доступу в промпти чи документи курсу. Якщо тека з такою назвою вже існує, перевір її вміст; не перезаписуй попередню роботу навмання.

## 2. Відкрий редактор і перевір Node.js

Можеш залишити свій звичний редактор. У [VS Code](https://code.visualstudio.com/download) вибери **File → Open Folder / Файл → Відкрити теку** й укажи корінь пакета, де лежить `package.json`. Якщо редактор запитує про довіру до теки, перевір, що це саме завантажений навчальний пакет, перш ніж дозволяти виконання його коду.

Тепер вибери **Terminal → New Terminal / Термінал → Новий термінал**. Унизу з’явиться місце для команд. Команди з блоків `sh` або з підписом «термінал» вводь тут по одній, натискаючи Enter. Промпти до AI підуть в окрему сесію пізніше.

```sh
node --version
npm --version
```

Перша команда має показати версію, що починається з `v22.` або `v24.`. Друга показує номер npm; точні молодші версії можуть відрізнятися. Якщо команда не знайдена або в тебе інша гілка Node, відкрий [офіційне завантаження Node.js](https://nodejs.org/en/download), вибери 22 або 24 та інсталятор для своєї ОС. Після встановлення відкрий новий термінал і повтори перевірку. Поки обидві команди не працюють, до встановлення залежностей не переходь.

За потреби перевір, де відкрито термінал: `pwd` у macOS/Linux або `Get-Location` у PowerShell. Це має бути та сама тека, яку видно в редакторі, безпосередньо біля `package.json`. Для наступних кроків не переходь у `docs/`, `lib/` чи іншу вкладену теку.

## 3. Встанови залежності й дочекайся перевірки

У цьому терміналі виконай:

```sh
npm ci
```

Дочекайся, поки команда завершиться й знову з’явиться запрошення вводу. Кількість встановлених пакетів і повідомлення npm залежать від середовища, тому не звіряй їх із картинкою лектора. Якщо встановлення завершилося помилкою, наступну команду поки не запускай.

```sh
npm run verify
```

У стартовому пакеті очікуємо два тести без падінь. Орієнтир для читання підсумку наведено нижче. Це приклад очікування, не результат твого запуску; оформлення рядків може відрізнятися:

```text
tests 2
pass 2
fail 0
```

Збережи фактичний підсумок свого термінала в тимчасовій нотатці. У кроці 6 перенесеш його у власний контекст. Ці два тести перевіряють health-відповідь і HTML-оболонку з CSP. Майбутній список сесій вони ще не перевіряють.

Якщо бачиш `ENOENT` із згадкою `package.json`, перевір поточну теку. Помилка мережі під час `npm ci` потребує перевірки з’єднання; не вимикай перевірку сертифікатів. Якщо процес перестав відповідати, збережи останній текст, перерви його через Ctrl+C і повтори після усунення причини. Не записуй помилку встановлення як невдалий тест поведінки.

## 4. Запусти сторінку й залиш її термінал відкритим

Після успішного `verify` введи:

```sh
npm run demo
```

Дочекайся повідомлення з адресою `http://127.0.0.1:4180`, скопіюй її в адресний рядок браузера й відкрий. На сторінці має бути `No slice is wired up yet.`. Це нормальний початок: у фікстурах лежать шість файлів сесій, але список із них ще не реалізований.

Команда `demo` продовжує працювати, доки сторінка потрібна. Відсутність нового запрошення вводу тут не означає зависання. Не вводь наступні команди в цей самий процес. Для іншої роботи відкрий **Terminal → New Terminal** у тому самому проєкті. Коли завершиш перегляд дашборда, повернися до його термінала й натисни Ctrl+C.

Для практики використовуй саме `npm run demo`: його `scripts/demo.mjs` явно задає абсолютний шлях до `fixtures/claude-home` і порт 4180. Значення `CLAUDE_HOME` чи `PORT` зі старого термінала їх не підмінять; `.env.fixtures` цей запуск не читає. `npm start` без налаштувань вказує на особисту `~/.claude`, тому тут його не запускаємо. Якщо порт зайнятий, перевір свій попередній запуск; чужі процеси не зупиняй.

## 5. Перевір, що Claude Code готовий

У цьому маршруті використовуємо встановлений Claude Code у терміналі. Це явна передумова до запиту агенту. У новому терміналі, знову біля `package.json`, перевір:

```sh
claude --version
```

Якщо бачиш номер версії, програма встановлена. Якщо команда не знайдена, постав відео на паузу. Нижче команди з [офіційного Quickstart Claude Code](https://code.claude.com/docs/en/quickstart). Вибери лише блок своєї ОС: він завантажує й запускає інсталятор, тому перевір адресу перед виконанням.

macOS, Linux або WSL, звичайний термінал:

```sh
curl -fsSL https://claude.ai/install.sh | bash
```

Windows, саме PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Дочекайся завершення. Відкрий новий термінал і повтори `claude --version`. Для помилок встановлення є [офіційна сторінка діагностики](https://code.claude.com/docs/en/troubleshoot-install).

Встановлення програми та доступ до сервісу є різними речами. Потрібен акаунт або доступ організації, який підтримує Claude Code. Не припускай, що будь-який доступ до чату автоматично дає доступ до цього інструмента. Цю передумову уточнює той самий Quickstart. Під час уроку не потрібно встановлювати SDD, купувати плагін або переходити в інший репозиторій.

Коли команда версії працює, запусти сесію:

```sh
claude
```

Під час першого запуску виконай вхід за підказками на екрані. Якщо потрібен окремий запит на вхід, введи `/login` уже **всередині Claude Code**, а не у звичайному shell. Перевір, що сесія відкрита в теці навчального пакета. Доступи підтверджуй лише для потрібної роботи; секрети й особисті логи не передавай.

## 6. Перший запит і повернення до вправи

Спочатку відкрий у редакторі `server.js`, `lib/claude/index.js`, `lib/sources.js`, `views/layout.js` і `test/skeleton.test.js`. Їх не потрібно читати напам’ять: ми хочемо знайти нинішній шлях від запиту до порожньої сторінки. Потім встав у відкриту сесію Claude Code:

```text
Прочитай CLAUDE.md і лише ці п’ять файлів:
server.js, lib/claude/index.js, lib/sources.js,
views/layout.js, test/skeleton.test.js.
Нічого не змінюй і не запускай команди. Особисті логи не відкривай.
Поясни, що зараз відбувається після відкриття / і /api/health.
Назви файли та функції, які це підтверджують.
Чи є вже функція, яка читає список сесій із диска?
Відділи виконуваний код від намірів у коментарях.
```

Дочекайся відповіді та звір її з відкритими файлами. Далі переходь до кроку 5 [чекліста](../../context-check.html#step-5): локальні правила → власний `02-context.md` → перевірка фактів → `handoff.md` → свіжа сесія → повторний `verify`. Вказівка «нічого не змінюй» задає межу завдання, але сама по собі не позбавляє інструмент технічних прав запису.

Перед свіжою сесією обов’язково збережи handoff. Усередині Claude Code введи `/exit`. Коли знову бачиш звичайний shell у теці пакета, запусти `claude` без відновлення розмови через resume чи continue. Передай новій сесії запит на читання handoff із [готових промптів](prompts.md). Запиши, яким інструментом фактично виконано перевірку.

## 7. Наприкінці перевір ZIP-копію без Git

Спочатку повтори `npm run verify` у звичайному терміналі робочої копії та збережи фактичний підсумок. Якщо користуєшся Git, переглянь `git status --short`, `git diff` і нові файли окремо. Для ZIP без Git-історії є команда порівняння нижче.

Збережений початковий ZIP розпакуй ще раз в окрему теку поза робочою копією. Використовуй той самий архів: свіже завантаження могло вже містити зміни автора. У недоторканій копії знайди корінь із `package.json`, але нічого там не редагуй й не встановлюй.

У терміналі робочої копії виконай:

```sh
node scripts/compare-kit.mjs "<path to unpacked untouched kit>"
```

Заміни текст усередині лапок на повний шлях до кореня недоторканої копії. Можеш скопіювати шлях у файловому менеджері або перетягнути теку в термінал. Перед Enter перевір, що шлях із пробілами має одну пару подвійних лапок, без додаткового екранування. У лапках має бути реальна адреса теки, без кутових дужок. Робоча й початкова копії мають лежати окремо, не одна всередині іншої.

Команда нічого не записує. Вона звіряє `package.name` обох копій, порівнює байти файлів і показує всі додавання, зміни та видалення. Ігноруються лише теки `node_modules`, `.git` і службові файли `.DS_Store`, `Thumbs.db`; `.claude/` перевіряється. Дати файлів не впливають на результат. Символічні посилання, зокрема в шляху до копії, не обходяться: за них або за помилки читання перевірка зупиниться з `ERROR`. Використовуй звичайні розпаковані теки.

Після уроку очікуємо такий список, якщо змінилися лише власні документи. Це приклад очікування, не виконана перевірка:

```text
ADDED   docs/practice/02-context.md
ADDED   docs/practice/handoff.md
SUMMARY added=2 changed=0 removed=0
```

`CHANGED` позначає змінені байти, `REMOVED` файл, який був у початковій копії та відсутній у робочій. Збережи свій фактичний вивід і поясни всі відмінності. Код завершення 1 тут означає знайдені відмінності, 0 означає їх відсутність, 2 означає помилку перевірки. Помилку не можна записувати як підтвердження чистого коду. Вміст двох власних документів перечитай окремо: команда лише показує відмінності, не оцінює правильність пояснень.
