# Підготовка до другого уроку

Тут ми запускаємо вже готовий навчальний застосунок, а потім встановлюємо SDD. Основні інструкції вже підготовлені. Новою буде лише карта, яку створить survey. Команди виконуй по одній і чекай, поки термінал знову запропонує ввід.

## 1. Завантаж і відкрий проєкт

Потрібні редактор, Git і Node.js 22 або 24. Встанови їх з офіційних сторінок: [VS Code](https://code.visualstudio.com/download), [Git](https://git-scm.com/downloads), [Node.js](https://nodejs.org/en/download). Після встановлення відкрий новий термінал.

Увійди у свій GitHub-акаунт і відкрий [репозиторій пакета](https://github.com/genkovich/agentic-engineering-mini-kit). Якщо бачиш 404, перевір акаунт і прийняте запрошення. Публічний чекліст не надає доступу до приватного коду; при проблемі звернися до команди курсу.

У терміналі перейди у власну теку для навчальних проєктів, яка не лежить усередині іншого Git-репозиторію. Скопіюй репозиторій:

```sh
git clone https://github.com/genkovich/agentic-engineering-mini-kit.git
cd agentic-engineering-mini-kit
```

При запиті входу використовуй свій налаштований GitHub-доступ. Токени не вставляй у промпт чи матеріали. Якщо тека вже існує, не перезаписуй її: перевір, чи це потрібна копія.

Альтернатива: **Code → Download ZIP**, потім розпакуй архів. Windows: **Extract All / Видобути все**; macOS: подвійне натискання. Працюй із розпакованою текою, де лежить `package.json`. Для ZIP нижче є короткий додатковий крок Git.

У VS Code вибери **File → Open Folder**, відкрий цю теку, потім **Terminal → New Terminal**. Перевір інструменти:

```sh
node --version
npm --version
git --version
```

Перша команда має показати `v22.` або `v24.`. Дві інші показують свої версії. Якщо команда не знайдена, повернися до встановлення; не продовжуй навмання.

## 2. Перевір і запусти застосунок

```sh
npm ci
```

Це встановлює залежності за `package-lock.json` і потребує інтернету. Дочекайся успішного завершення. `ENOENT` зі згадкою `package.json` зазвичай означає неправильну теку: перевір її в редакторі й відкрий новий термінал.

```sh
npm run verify
```

Очікуємо два тести без падінь. Приклад підсумку, це не результат твого запуску:

```text
tests 2
pass 2
fail 0
```

Ці тести перевіряють health-відповідь і HTML-оболонку. Список сесій вони ще не перевіряють, бо він не реалізований. Збережи фактичний вивід у своїх звичайних нотатках або історії термінала; окремий документ для цього уроку не вимагається.

### Відкрий початкову сторінку

```sh
npm run demo
```

Дочекайся адреси http://127.0.0.1:4180 і відкрий її в браузері. Має бути `No slice is wired up yet.`: шість навчальних файлів сесій лежать на диску, але списку на сторінці ще немає.

Цей термінал зайнятий сервером. Для наступних команд відкрий **Terminal → New Terminal** у тій самій теці. Завершується сервер через **Ctrl+C**. При `EADDRINUSE` порт 4180 зайнятий: зупини власний попередній запуск. Невідомі процеси навмання не завершуй.

Запуск через `scripts/demo.mjs` примусово задає фікстури та порт 4180. Перед ним `predemo` вирівнює дати файлів. Не використовуй `npm start` і особисту `~/.claude` для цієї практики. Можна додатково відкрити http://127.0.0.1:4180/api/health і перевірити, що `claudeHome` вказує на `fixtures/claude-home`.

## 3. Підготуй Git, агента й SDD

Survey записує карту в Git і привʼязує її до коміту. Тому перед його запуском потрібна власна Git-копія.

Якщо був clone, виконай:

```sh
git rev-parse --show-toplevel
git status --short
```

Перший результат має бути шляхом саме до відкритої копії пакета. Якщо показано батьківську теку, зупинись: перенеси навчальну копію поза чужий репозиторій і відкрий її заново. Не запускай SDD у корені особистих нотаток чи іншого проєкту.

Якщо був ZIP, відкрий термінал у розпакованій теці пакета і виконай:

```sh
git init
git rev-parse --show-toplevel
```

Звір корінь так само. Для обох способів перевір автора комітів:

```sh
git config user.name
git config user.email
```

Якщо значень немає, задай свої **локально для цього репозиторію**. Заміни текст у лапках на своє імʼя та адресу, яку дозволяєш бачити в комітах. Можна взяти власну GitHub noreply-адресу з налаштувань акаунта:

```sh
git config user.name "YOUR NAME"
git config user.email "YOUR COMMIT EMAIL"
```

Після ZIP потрібен перший коміт. Спершу переглянь `git status --short`: там мають бути тільки файли навчального пакета, без секретів і чужих документів. Потім:

```sh
git add .
git diff --cached --stat
git commit -m "Start mini-course practice"
```

Після clone початковий коміт уже є; ці три команди повторювати не потрібно. Зміни нікуди не публікуємо.

У редакторі відкрий `.claude/sdd.local.example.md`, вибери **File → Save As** і збережи як `.claude/sdd.local.md`. Це налаштування мови та простого послідовного режиму. Файл уже виключений через `.gitignore`. Наявний власний файл не перезаписуй.

Перед першим скілом постав мітку:

```sh
git tag start
```

Це мітка на стан до практики, щоб наприкінці побачити всі зміни однією командою.

### Claude Code: основний показ у відео

У звичайному терміналі перевір:

```sh
claude --version
```

Якщо команда не знайдена, постав відео на паузу. Вибери команду своєї ОС з [офіційного Quickstart](https://code.claude.com/docs/en/quickstart). Інсталятор завантажується і виконується; перед запуском перевір адресу.

macOS, Linux або WSL:

```sh
curl -fsSL https://claude.ai/install.sh | bash
```

Windows, саме PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Відкрий новий термінал і повтори `claude --version`. Якщо запуск досі не працює, звір помилку з [діагностикою](https://code.claude.com/docs/en/troubleshoot-install).

Встановлена програма ще потребує акаунта або доступу організації, який підтримує Claude Code. Виклики агента оплачуються за твоїм тарифом; сам дашборд і тести модель не викликають.

```sh
claude
```

Під час першого запуску пройди вхід за підказками. Для повторного входу є `/login` усередині Claude Code. Перевір показану теку проєкту та довіряй лише завантаженій навчальній копії. Під час запису не показуй токени й особисті дані.

Наступні команди вводь **усередині Claude Code**, по одній:

```text
/plugin marketplace add genkovich/sdd
/plugin install sdd@sdd
/reload-plugins
```

Відкрий список команд через `/` і знайди `/sdd:survey`. Якщо команда відсутня, перевір повідомлення встановлення, повтори reload або перезапусти Claude Code в цій самій теці. Не вигадуй заміну команди. [Офіційний репозиторій SDD](https://github.com/genkovich/sdd) містить актуальні інструкції.

### Codex або Cursor: вибери один інструмент

Якщо вже працюєш у Codex чи Cursor, Claude Code встановлювати не потрібно. Відкрий ту саму теку пакета в обраному інструменті. Потрібен власний доступ до його агента.

Для Codex CLI офіційна [інструкція запуску](https://developers.openai.com/codex/cli) пояснює встановлення й вхід. Перевір `codex --version` і запускай `codex` з кореня пакета.

SDD для Codex або Cursor встановлюється скриптом у поточний проєкт. На Windows виконуй його у Git Bash або WSL, не в PowerShell. Перед запуском перевір адресу: скрипт завантажується й виконується.

**Codex**, у звичайному терміналі кореня пакета:

```sh
curl -fsSL https://raw.githubusercontent.com/genkovich/sdd/main/install.sh | bash -s -- codex
```

Перезапусти Codex. У розмові команда карти має назву `$sdd-survey`. Не встановлюй паралельно другий варіант SDD через marketplace: назви й дублікати команд відрізнятимуться.

**Cursor**, у звичайному терміналі кореня пакета:

```sh
curl -fsSL https://raw.githubusercontent.com/genkovich/sdd/main/install.sh | bash -s -- cursor
```

Перезапусти Cursor або виконай **Developer: Reload Window**. У чаті введи `/` й вибери `sdd-survey`.

Скрипт додає `.agents/skills/` і `.codex/agents/` для Codex або `.cursor/skills/` і `.cursor/agents/` для Cursor. Це очікувані службові файли встановлення. Порівняй їх із поясненням [SDD](https://github.com/genkovich/sdd), не сприймай появу цих тек як реалізацію фічі.

## 4-8. Прочитай інструкції, створи й перевір карту

Виконуй [повідомлення з відповідними номерами](prompts.md). Основні інструкції лежать у `AGENTS.md`, HTML-інструкції у `views/AGENTS.md`, політика даних у `docs/rules/session-data.md`.

| Інструмент | Як підключається зміст |
|---|---|
| Claude Code | Кореневий `CLAUDE.md` імпортує `AGENTS.md`; вкладені інструкції й scoped rules підключаються при читанні відповідних файлів |
| Codex | На початку збирає `AGENTS.md` від кореня до робочої теки; запуск із кореня не гарантує автоматичне включення `views/AGENTS.md` |
| Cursor | Правило з `globs` підключається, коли відповідний файл є в контексті; підтримує також `AGENTS.md` |

Кореневий AGENTS прямо вимагає читати вкладені інструкції та політику перед відповідною роботою. Завдяки цьому є явний спосіб дістати правила незалежно від автоматичного механізму.

Документація: [Claude Code](https://code.claude.com/docs/en/memory), [Codex AGENTS.md](https://developers.openai.com/codex/guides/agents-md), [Cursor rules](https://cursor.com/docs/context/rules). Явне читання не доводить автоматичного підключення; текст правила не замінює права доступу.

## 9. Перевір нову сесію

Спочатку збережи перевірену `docs/architecture-map.md`. Потім:

- Claude Code: `/exit`, далі `claude` у звичайному терміналі тієї самої теки, без resume або continue.
- Codex: `/new` у поточній CLI-сесії.
- Cursor: новий чат у тому самому проєкті без копіювання старої розмови.

Передай [запит кроку 9](prompts.md#9-нова-сесія). Перевір відповідь за кодом, інструкціями й картою. Запиши у поля чекліста, який інструмент використано, що він пояснив правильно, які файли відкрив явно й що залишилося неперевіреним.

## 10. Переглянь зміни й збережи результат

Повтори `npm run verify`. Далі порівняй поточний стан із міткою `start` із кроку 3:

```sh
git log --oneline start..HEAD
git diff start HEAD
git diff HEAD
git status --short
```

Перша команда показує нові коміти. Друга показує закомічені зміни. Третя показує зміни після останнього коміту; нові невідстежувані файли видно в останній команді, їх відкрий окремо. Якщо survey не робив коміта, перші дві команди нічого не покажуть, а карта буде видна в `git status --short`.

Очікуємо карту та службові зміни обраного способу встановлення SDD. Код, тести й залежності залишаються незмінними. Уточнення інструкцій допустиме лише після твоєї перевірки та погодження. Якщо карта вже точна, переписувати її або правила для позначки не потрібно.

У [чеклісті](https://genkovich.github.io/ai-work-check/context-check.html#evidence) є поля для інструмента, фактичних запусків, перевірки нової сесії та обмежень. Вони не зберігаються автоматично. Натисни **Зберегти результат текстом** до закриття сторінки; отримаєш один Markdown-файл із позначками й власними записами. Не вставляй секрети або приватні розмови.
