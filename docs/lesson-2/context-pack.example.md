# Приклад контексту для session-index

Це заповнений навчальний приклад. Твердження нижче можна звірити з виданим скелетом. Запусків у твоєму середовищі цей документ не підтверджує; результати команд потрібно записати у власному файлі.

## Мета

Підготувати контекст для S1: показати перелік сесій, зібраний із метаданих файлів. У цьому уроці реалізацію не починаємо.

## Що працює зараз

`server.js`, обробник `/api/health`, повертає стан сервера, налаштовану домашню теку Claude і список зареєстрованих джерел. Обробник `/` викликає `layout()` та `empty()` і показує «No slice is wired up yet.». Сесії з диска він ще не перелічує.

У `lib/claude/index.js` є `claudeHome()`, `projectsDir()` і реєстрація адаптера з полями `id`, `label`, `home`. У `lib/sources.js` є реєстр. Його коментар обіцяє відсутність прямих імпортів адаптера, але `server.js` напряму імпортує `claudeHome()`. Коментар не підтверджує поточну архітектуру.

Наявний шлях сторінки: HTTP-запит `/` → обробник у `server.js` → `layout()` і `empty()` у `views/layout.js` → порожній HTML. Звʼязку від файла сесії до рядка переліку ще немає.

## Що має зʼявитися в S1

За `docs/roadmap.md` та `docs/idea-brief.md` індекс використовує метадані файлів. Потрібні перелік на сторінці й JSON-маршрут, порядок від свіжих до старих, похідна назва проєкту з відповідною позначкою та порожній стан для відсутньої теки. Точні інтерфейси погоджуються у специфікації наступного уроку.

Фікстури містять шість верхньорівневих файлів сесій у трьох проєктах. Вкладені `subagents/` і `tool-results/` не є додатковими сесіями. Вміст JSONL, людські заголовки, таймлайн, токени й друге джерело до S1 не входять.

## Рішення й обмеження

D1 приймаємо з roadmap: сесією є файл безпосередньо в теці проєкту. D2 також приймаємо: назва проєкту похідна й має позначку. Для D3 погоджено параметр ліміту без пагінації; конкретне значення за замовчуванням потрібно визначити під час специфікації.

Практика використовує `.env.fixtures` та `npm run demo`. Особисті логи не підключаємо. Перевірка здоровʼя й оболонка з CSP мають зберегтися; наявні тести містяться в `test/skeleton.test.js`. Локальні правила: `views/CLAUDE.md` і `.claude/rules/session-index.md`, загальні: `CLAUDE.md`.

## Перевірки

У вихідному коді визначено два тести скелета. Фактичний результат `npm run verify` у твоєму середовищі: **ще не внесено**. Стан сторінки після твого запуску: **ще не внесено**. Відповідь свіжої сесії: **ще не внесено**.

Для власного запису додай дату, версію пакета, дослівний результат своїх перевірок і виправлені неточності. Цей приклад не можна використати замість них.
