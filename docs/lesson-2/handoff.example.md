# Приклад handoff для другого уроку

Це навчальний зразок передачі стану скелета. Уяви, що наступна сесія не бачила жодного твого повідомлення: їй потрібні мета, адреси файлів і чесний стан перевірок. Саме для цього розділи нижче. Перед виходом із Claude Code через `/exit` запиши власний `docs/practice/handoff.md` та підстав лише перевірені відомості. Приклад не є звітом про твою роботу.

## Де ми зупиняємося

Працюємо з `agent-ops-dashboard`, майбутній зріз `session-index`. Зараз є `/api/health` і порожня сторінка `/`. Читання переліку сесій ще не реалізоване. Мета наступної сесії в межах уроку 2: перевірити контекст і пояснити стан; код не змінювати.

## Що прочитати

Почни з `CLAUDE.md` і власного `docs/practice/02-context.md`. Потім відкрий `views/CLAUDE.md`, `.claude/rules/session-index.md` та файли коду, на які посилається контекст. За потреби звір терміни в `CONTEXT.md`, D1–D3 у `docs/roadmap.md` і поточні модулі в `docs/architecture-map.md`.

## Що передаємо

Для прикладу прийняті D1 і D2 з roadmap. Для D3 значення ліміту лишається до специфікації. Коментар `lib/sources.js` про відсутність прямих імпортів не відповідає `server.js`; це вже відома розбіжність, яку потрібно зберегти в поясненні.

У S1 індекс читає метадані файлів і пропускає вкладені артефакти. Особисту `~/.claude` не використовуємо. Для запуску є `npm run demo` на фікстурах. Наявну перевірку здоровʼя та CSP зберігаємо.

## Чого цей приклад не підтверджує

Фактичний вивід `npm run verify`, стан твоєї сторінки й результат свіжої сесії сюди не внесені. Власні змінені файли також потрібно назвати окремо. Якщо перевірка не виконана, запиши «не перевірено», без готового зеленого звіту.

## Наступний крок

Після читання поясни поточну й заплановану поведінку окремо, назви джерела тверджень і невирішені питання. Людина звірить відповідь із кодом. У разі неточності виправляємо контекст та повторюємо перевірку; реалізація починається в наступних уроках.
