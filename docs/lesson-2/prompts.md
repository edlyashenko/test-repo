# Запити для роботи з контекстом

Ці повідомлення можна вставляти у звичайну сесію coding-агента, відкриту в корені пакета. Вони не потребують додаткових skills. Перед підтвердженням змін переглянь, які файли агент збирається редагувати.

## Прочитати локальні правила

```text
Прочитай CLAUDE.md, views/CLAUDE.md і .claude/rules/session-index.md.
Код не змінюй. Поясни, для якої частини проєкту потрібен кожен файл.
Порівняй шлях lib/claude/index.js із патерном lib/claude/**/*.js.
Чи підходить під цей патерн views/layout.js?
Відокрем текст вимоги від доказу її виконання.
Явне читання в цьому запиті не називай перевіркою автозавантаження.
```

## Звірити власний контекст

```text
Прочитай docs/practice/02-context.md, CLAUDE.md, views/CLAUDE.md,
.claude/rules/session-index.md, CONTEXT.md, docs/architecture-map.md
і рішення D1-D3 у docs/roadmap.md. Звір твердження з server.js,
lib/claude/index.js, lib/sources.js, views/layout.js і test/skeleton.test.js.
Не змінюй код, тести, налаштування чи документи. Приклади в examples/ не читай.
Відокрем те, що працює зараз, від майбутнього S1 session-index.
Для кожної неточності покажи файл і функцію або рядок.
Питай лише про рішення, яких справді бракує; наявні вибори roadmap не вигадуй заново.
Наприкінці запропонуй короткі правки тільки до docs/practice/02-context.md.
Дочекайся мого рішення перед редагуванням.
```

## Записати передачу перед паузою

```text
Підготуй docs/practice/handoff.md для продовження уроку 2 в новій сесії.
Запиши мету, поточний стан скелета, шлях до docs/practice/02-context.md,
правила й файли коду для читання, погоджені рішення, змінені файли,
фактичні команди та результати, невідоме й наступний крок без реалізації.
Використовуй лише перевірені відомості цієї сесії. Якщо запуску немає,
напиши «не перевірено». Не копіюй результати з навчального прикладу.
Не додавай секретів, особистих логів чи приватних шляхів.
Змінювати можна лише docs/practice/handoff.md.
```

## Продовжити в новій сесії

```text
Прочитай docs/practice/handoff.md, зазначений у ньому контекст,
кореневі й локальні правила та відповідні файли коду.
Файли не змінюй, session-index не реалізуй, examples/ не читай.
Поясни, що працює зараз, що має додати S1 і що до нього не входить.
Назви файли та функції, якими підтверджуються поточні факти.
Окремо назви вимоги з документів, фактичні результати перевірок і невідоме.
Не вважай позначки чекліста доказом і не домислюй пропущених запусків.
```

У Claude Code для нової розмови можна використати `/clear`; в іншому інструменті відкрий нову сесію його звичайним способом. Спочатку перечитай і збережи handoff. Жоден із цих запитів не перевіряє, чи інструмент завантажив правила автоматично: ми прямо просимо їх відкрити.
