# Idea brief - agent-ops-dashboard

**Що це.** Local-first дашборд поверх логів агентних сесій Claude Code. Читає лише `CLAUDE_HOME` (типово `~/.claude`), нічого туди не пише. Навчальний проєкт курсу «Agentic Engineering»: пакет учасника починається зі скелета, і кожен наступний крок це тонкий зріз, який видно на сторінці.

**Кому.** Розробник або команда, що вже працює з Claude Code і хоче на власні очі бачити, що роблять їхні агентні сесії: скільки їх, у яких проєктах, коли вони були активні, які інструменти викликалися, скільки коштують токени, що відбувається наживо.

**Що вже є (S0, готово).** Скелет: Express-сервер з `/api/health` і сторінкою «No slice is wired up yet», спільний layout і CSS, реєстр джерел `lib/sources.js`, адаптер Claude, який поки що вміє лише назвати домашню теку, синтетичні фікстури на шість сесій у трьох проєктах (плюс `subagents/` і `tool-results/` як шум) і два тести на скелет.

**Чого немає і болить.** Дашборд не показує жодної сесії. Розробник відкриває сторінку і бачить порожній стан, хоча на диску лежать шість файлів сесій. Немає індексу, немає переліку, немає порядку «що було останнім».

**Наступний крок беклогу.** Індекс сесій: перелік файлів сесій із проєктом, розміром і часом останньої зміни, від свіжих до старих, лише з метаданих файлової системи (fstat), без читання вмісту. Порожній стан лишається для порожньої або відсутньої теки. Розмір S: один модуль читання диска, один маршрут, одна сторінка.

**Далі за індексом (ідеї без обіцянок).** Людські заголовки сесій з `ai-title` у файлі; таймлайн подій однієї сесії; облік токенів із дедуплікацією по `message.id`; live tail через SSE; аналітика по днях із чесним `scanned`/`skipped`; другий агент-джерело (наприклад Codex) за контрактом `registerSource`; розбивка аналітики по інструментах і сесіях; порівняння агентів.

**Межі.** Нічого не пишеться назад у `CLAUDE_HOME`. Метрика використання контекстного вікна не показується (даних немає в транскриптах). Дашборд рахує лише те, що бачить на диску, і зізнається, чого не бачить.
