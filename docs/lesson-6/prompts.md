# Урок 6. Два запити для роботи з підсумком

Ці запити допомагають прочитати досвід, який уже є в проєкті. Вони не запускають нову реалізацію чи приймання. Перед використанням пройди [практику](README.md), щоб розуміти, який результат потрібний.

## A. Підготувати підсумкову записку

Надішли в чат агента у своїй копії кіта. Якщо початковий результат анкети збережений поза проєктом, самостійно прочитай його й додай потрібні відповіді без особистих даних. Агенту не потрібно шукати файли по всьому компʼютеру.

~~~text
Допоможи підготувати docs/practice/06-delta.md за templates/06-delta-audit.md для моєї session-index.

Спочатку прочитай AGENTS.md, шаблон, docs/practice/05-verification.md і лише потрібні посилання з цієї записки. За потреби звір попередні docs/practice/04-workflow.md, docs/features/session-index/spec.md та sad.md. Не читай examples/, особисті логи, секрети або файли поза цим проєктом. Скажи, яких потрібних документів немає.

Покажи точний CANDIDATE_COMMIT і рішення з уроку 5. HEAD не підставляй замість перевіреного кандидата. Факти з наявних доказів залиш із їхніми версіями й датами. Не запускай тести, сервер, SDD, install, git write, push чи deploy.

Склади чернетку пʼяти частин шаблону. Для пʼяти рядків порівняння назви факти з цієї задачі та джерела. Особисті стартові відповіді не вигадуй. Якщо початкового запису немає серед наданих матеріалів, напиши «початкового запису немає». Один прохід не називай сталою звичкою, бали різних анкет не порівнюй, приріст продуктивності не обчислюй.

Запропонуй один висновок зі справжнього спостереження: проблема, прогалина або вдалий механізм. Відділи підтверджену причину від гіпотези. Не вигадуй дефект чи RED/GREEN. Запропонуй одну наступну дію з перевіркою; дату й остаточний вибір залиш мені.

Можеш створити лише docs/practice/06-delta.md. Якщо він уже заповнений, спершу покажи пропоновані зміни в чаті без перезапису. Інші файли не змінюй. Наприкінці переліч, що заповнено за джерелами, а що маю вирішити я. Статус приймання фічі не підвищуй.
~~~

## B. Перевірити висновки без редагування

Запит для свіжої сесії або колеги. Після відповіді відкрий названі місця й прийми рішення самостійно.

~~~text
Перевір логіку docs/practice/06-delta.md для session-index. Це review підсумкової записки, не повторне приймання коду й не дозвіл щось реалізовувати.

Прочитай AGENTS.md, записку й лише потрібні джерела всередині цього проєкту. Не читай examples/, особисті логи або секрети. Не редагуй файли; не запускай тести, сервер, SDD, install, git write, push чи deploy.

Перевір пʼять речей:
1. Чи є джерело для кожного важливого факту; чи відсутній стартовий запис не відновлено з памʼяті.
2. Чи CANDIDATE_COMMIT і рішення узгоджені з docs/practice/05-verification.md; чи старі докази не приписано новій версії.
3. Чи один випадок не названо звичкою; чи немає числового порівняння різних анкет або непідтвердженого виграшу швидкості.
4. Чи висновок відрізняє спостереження, гіпотезу, перевірений механізм і реальне блокування. Якщо причини не доведено, це має бути видно.
5. Чи наступна дія посильна, має дату та спосіб перевірки; чи рефлексія не підміняє приймання всієї фічі.

Для кожного зауваження поверни місце в записці, що саме не підтверджено, потрібне джерело або запитання до мене. Якщо зауважень немає, назви обсяг і межі читання. Не вигадуй знахідку для заповнення звіту. Жодних правок файлів.
~~~
